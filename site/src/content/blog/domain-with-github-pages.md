将自定义域名绑定到 GitHub Pages，核心流程并不复杂，主要分为 **“在 GitHub 端声明域名”** 和 **“在 DNS 端配置解析”** 两步。下面是一份从准备到排错的完整指南。

###  准备工作

开始前，请确保你已经满足以下条件：

- 拥有一个**已注册的域名**，并能登录其 DNS 管理后台（如阿里云、腾讯云、Cloudflare、Namecheap 等）。
- 已在 GitHub 仓库中**成功启用了 GitHub Pages**，并能通过默认的 `username.github.io` 地址正常访问。
- 你拥有该仓库的**管理员权限**，可以进入 Settings 页面。

###  第一步：在 GitHub 仓库中配置自定义域名

这一步的目的是告诉 GitHub：“这个域名属于我，请用这个域名来展示我的网站”。

1. 进入你的 GitHub 仓库页面，点击顶部的 **Settings**（设置）。
2. 在左侧边栏的 “Code, planning, and automation” 部分下，点击 **Pages**。
3. 在 **Custom domain**（自定义域）输入框中，填入你的完整域名（例如 `www.example.com` 或 `example.com`），然后点击 **Save**（保存）。
4. 保存后，GitHub 会自动在你的仓库根目录创建一个名为 `CNAME` 的文件，文件内容就是你刚刚填写的域名。**请注意不要手动删除或修改这个文件**，它用于确保你的站点在重新部署后仍保留自定义域名设置。

###  第二步：在 DNS 服务商处配置解析记录

这一步的目的是告诉互联网：“访问这个域名时，请去 GitHub Pages 的服务器获取内容”。根据你使用的域名类型（根域名 vs 子域名），配置方式有所不同。

**方案一：使用子域名（如 `www.example.com` 或 `blog.example.com`）**

这是最简单、最推荐的方式。你只需要在 DNS 管理后台添加一条 **CNAME 记录**。

| 记录类型 | 主机记录（名称） | 记录值（目标） |
|---|---|---|
| CNAME | `www`（或 `blog`） | `你的用户名.github.io` |

例如，若你的用户名是 `octocat`，则记录值填 `octocat.github.io`。

**方案二：使用根域名（如 `example.com`）**

根域名（也称 Apex 域名）不能直接使用 CNAME，你需要添加 **A 记录**，指向 GitHub Pages 的四个官方 IP 地址。

| 记录类型 | 主机记录（名称） | 记录值（目标） |
|---|---|---|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |

> **注意**：DNS 更改可能需要几分钟到 24 小时才能在全球范围内生效，请耐心等待。

###  第三步：启用 HTTPS 强制

当 DNS 配置生效后（通常等待几分钟到几小时），回到仓库的 **Settings → Pages** 页面。

1. 如果看到 **Enforce HTTPS**（强制 HTTPS）选项变为可勾选状态，**勾选它**。GitHub 会自动为你的域名申请并部署免费的 TLS 证书（由 Let‘s Encrypt 提供），此后所有访问都将通过安全的 HTTPS 进行。
2. 如果该选项为灰色不可用，通常说明 GitHub 还未完成 DNS 检查或证书签发。可以稍等片刻再刷新页面，或参考下文的排错部分。


###  常见问题排错

- **域名打不开，或提示“DNS check unsuccessful”**：首先用 `dig yourdomain.com`（macOS/Linux）或 `nslookup yourdomain.com`（Windows）命令检查 DNS 是否已解析到正确的 GitHub IP 或 CNAME 目标。确认 DNS 记录**没有拼写错误**，且 TTL 不要设置过长（如 14400 秒），以免影响调试。
- **Enforce HTTPS 始终灰色不可选**：这是最常见的问题。除了等待证书签发（有时需要 24 小时），可以尝试一个官方社区总结的技巧：**将 Custom domain 输入框清空并保存，等待几分钟后再次填入域名保存**，这有时能触发证书的重新申请流程。
- **访问到旧页面或内容不更新**：尝试清除浏览器缓存，或使用无痕模式访问。如果使用了 Cloudflare，可以尝试清除 Cloudflare 的缓存。
- **仓库迁移后域名失效**：请检查**旧仓库**的 Pages 设置中是否还残留着自定义域名配置，以及旧仓库分支中是否存在 `CNAME` 文件。删除旧配置，并在新仓库中重新设置。

完成以上步骤后，你的自定义域名就应该能正常访问 GitHub Pages 站点，并自动跳转到 HTTPS 了。
